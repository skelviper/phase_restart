# AGENTS.md

## 任务

从去掉单倍型列的 `data/P9016.pairs.gz` 重建 P9016 小鼠单细胞的**二倍体**三维结构：在**一个共享核体积**中联合拟合 40 条轨迹（20 条染色体 × 2 个拷贝），使用全部 1,703,888 条接触（cis 和 inter），并诚实测量仅凭接触能够恢复多少真实单倍型拆分。

**范围说明（当前）。**工作范围是全基因组，不是逐染色体。染色体间接触用于空间放置约束（染色体空间分区、装入一个球体）。见 `docs/PLAN-genome-allele-split.md`。Stage 1 的逐染色体评估工具检查已完成，不再是关键路径。

参考目标仅用于评估：`data/P9016.1m.3dg.gz`（1 Mb、40 条染色体-拷贝轨迹）。

### 保持以下三个主张分开，绝不合并

| | 主张 | 当前状态 |
| --- | --- | --- |
| **L1** | 混合接触包含与两套结构差异相关的*可预测*信号。 | **chr1 支持**（相对于同一记录集随机拆分为 +0.0767 [+0.0480, +0.1045]，F16）。chrX 在 891/1,059 个配对上为 +0.0400 [+0.0007, +0.0914]，属于边缘证据。chrX 的定相率是常染色体的一半（15.3% 对 31.0%），因此其 oracle 使用的已知拷贝接触少 3.3x，留出配对集合小 35%（F17）。 |
| **L2** | 沿整条染色体一致地恢复拆分*（长程拷贝身份，而不只是局部正确片段）*。 | **尚未证明。**Stage 1 解决了前置问题：该*分数*不会忽略全局错接（F13），所以目标是合理的，冻结的 `Z` 不是必然结果。但目前没有方法被证明能够达到一致拆分。这仍是开放问题。 |

L1 **不**推出 L2。Stage 1 表明，在 chr1 上，留出判据把整条染色体一致拆分排在所有预注册错接替代之前（全部三个评估工具类别），因此“局部正确、全局错接”**会**受到评估工具惩罚。这不表示盲方法能够找到一致拆分；评估工具的分辨能力取决于三个逐染色体量的共同作用——完整定相训练记录、它们覆盖 bin 的均匀程度和留出配对数——而不只是深度（F17）。chrX 在三者上都处于不利端。

## 严格科学边界

- 训练侧绝不能看到 `phase0`、`phase1`、`phase_prob00..11` 或其派生物，也不能看到 reference 3DG。`run.py prepare` 恰好写出七列；加载器必须硬拒绝 `#columns` 行含有 phase 字段的文件。
- 只有候选坐标写出并完成哈希后，评估器才可以读取 phase 列和 3DG。
- `copyA`/`copyB` 是规范标签。跨拷贝指标按几何为每条染色体选择最佳互换，并写明该政策。
- **染色体间接触不携带母源/父源标签信号**（同单倍型 70,558，对不同单倍型 76,438）。绝不能用它们计算单倍型准确率；它们**确实**用于空间放置（染色体空间分区和核内装箱）——这是当前项目政策，不是可能性。两句话相互独立：没有标签信号，但有真实几何信号。
- **计数目标具有精确的 `2^20` 对称性。**对于任意染色体子集，`lambda` 在 `u_c -> -u_c` 下不变（`u_c = (X_c - Y_c)/2`），因为每个观测计数都是拷贝组合之和。因此 (a) 每条染色体的 A/B 全局标签是规范自由度，(b) 加入 inter 接触**不会**打破对称性，(c) 数据真正决定的是 `u_c` 是否沿染色体形成一个*连贯场*。任何方法都必须显式离开 `u = 0`；见计划。
- 候选重构由**所有接触上的无标签计数似然**选择（当前计划没有留出折）。reference 3DG 可以*读取*来报告 R1/R2/R3，但绝不能用它选择超参数。
- 20 条染色体是**同一个细胞**中的 20 个关联测量。bootstrap 区间描述该细胞内的技术/结构变异，不是生物学重复。

## 更正后的协议（每个指标都必须遵守）

第一代结果违反了前四条，见 `docs/exploration/README.md`。第 5、6 条是在 Stage 1 后加入的。

1. **基因组坐标用数值比较。**对字符串使用 `c[2] > c[4]` 会静默丢掉 1,135,454 条染色体内接触中的 147,005 条（12.95%）。
2. **绝不按基因组间隔的函数拆分数据折。**`(i*7919 + j*104729) % 2` 等于 `(i+j) % 2`——即 bin 距离的奇偶性——并把每个同区间对送入测试折。使用数值配对的混合哈希，优先使用训练/验证/测试折。
3. **绝不在测试折上选择超参数。**距离指数在验证折上选择。
4. **同区间（零距离）对从结构指标中排除并单独报告。**它们占染色体内接触的 438,774/1,135,454（38.64%），不携带结构信息；它们也是使参考准确率膨胀的全部“平局”来源。
5. **每个两拷贝比较都使用规范不变策略**（Stage 1 后加入）。原生引擎的两拷贝拟合对 `copyA`/`copyB` **不**对称：重新标记所有接触会使 chr1 留出 rho 改变 0.0220（F15）。报告候选及其标签互补版本相对于 `oracle` 及其互补版本的均值，或使用对互补不变的构造（`rewire` 规则，或无规范的 `splice` 评估工具）。
6. **`hickit -s` 不是独立重复。**F14 曾记录不同 seed 的 `.3dg` 输出逐字节相同，但 S2 审查发现当时 Stage 1 wrapper 把 `-s` 放在 `-b` 后面，因此该命令没有给实际拟合设 seed。正确顺序的原生 seed 只构成优化初始化重复；独立拟合对照仍须改变*数据*（例如训练折的不相交半集）。见 `docs/REVIEW-s2-observation-model.md`。
7. **`hickit -b` 在解析时运行 FDG 拟合。**`-n` 必须出现在 `-b` **之前**（`-n 3000 -b1m`），否则迭代数会静默保持默认 1000。
8. **当前计划没有训练/测试拆分。**所有接触拟合每个候选。超参数只由无标签计数似然选择，绝不由 reference 比较选择；reference 仅是报告用的上限。

## 无标签判据

对任意候选拆分，只在**训练折**上用原生 FDG 拟合结构，然后根据**留出**区间对计数，以 `d_A^-a + d_B^-a` 与观测总计数的 Spearman 进行评分。指数 `a` 在验证集上选择。

更正后的基线为 `docs/exploration/benchmark_v1.py`，覆盖全部 20 条染色体并排除同区间：

| 预测器 | 平均留出 rho |
| --- | ---: |
| 两个结构，**oracle** 拆分 | **0.5856** |
| 两个结构，随机拆分 | 0.5127 |
| 一个结构（共识） | 0.5087 |

`oracle − random = +0.0729 ± 0.0520`，oracle 在 **20 条中的 19 条染色体**获胜，逐染色体 bootstrap CI 在 15/20 条染色体上排除 0。**chrX 为负（−0.090）**，chr7、chr14、chr17、chr19 的 CI 跨过 0。早先膨胀的数值（0.689 / 0.648 / 0.641，+0.041）来自错误协议；更正后的差异反而*更大*。

**为什么绝对差距看起来小。**分数由共享成分主导。chr1/2/3 的基因组间隔只有 0.47/0.44/0.52；共识 3D 为 0.63/0.59/0.63；oracle 拆分为 0.64/0.58/0.59。应根据**相对对照的配对差值**判断，绝不能看绝对值。

### 已建立与尚未建立的障碍

计数决定的是**总和** `lambda_A + lambda_B`，它关于半差场 `w = (X - Y)/2` 为偶函数。需要避免一个常见的过度表述：

- **正确：**拆分符号在计数中不是一阶信号。所有基于这些计数的目标关于 `w` 都为偶函数，因此 `w = 0`（塌缩）的一阶导数为零，是 hard-assignment 循环的精确自洽固定点。
- **此前过度表述：**偶性**不**意味着 `w = 0` 是所有方法的稳定吸引子。`(u^2-1)^2` 在 0 处为驻点，而 0 是其局部最大值。已测得的只是随机初始化在**该**循环中不会逃逸，不是任何非线性求解器都不能逃逸。
- **此前也过度表述：**“计数只沿共识方向依赖 `delta^2`。”横向扰动不改变 `d_A - d_B`，但会把**两个**距离移到 `sqrt(1+t^2)`，因此会改变总和。可观测量关于整个向量 `w` 为偶函数，而不只是关于其在 `vhat` 上的投影为偶函数。它比早期说明所称的可观测量更丰富。

## 阶段计划

### Stage 0——更正基线（已完成）及其冻结

`docs/exploration/benchmark_v1.py` 实现更正协议。`explore_estep_fixed.py` 给出更正后的参考准确率。在开展任何方法工作前，将两者冻结为项目回归基线。

### Stage 1——片段交换实验（已完成）

运行 `test_res/007-20260912_124000-stage1-fragment-swap-chr1`、`008-…-fragment-swap-chrX` 和 `009-…-depth-control-chr1-as-chrX`。设计冻结在 `docs/STAGE1_PREREGISTRATION.md`；数字见 `MEASURED_FACTS.md` F13–F20。规范运行是 `test_res/007-…`（chr1）、`008-…`（chrX）和 `009-…`（chrX 训练深度下的 chr1）。

**chr1 答案：是。**该分数不会忽略全局错接。一个 20 Mb 结构墙被 pooled 规范不变判据检测到（+0.0243 [+0.0055, +0.0434]）；5 Mb 和 10 Mb 墙被无规范 `splice` 评估工具检测到（+0.0151、+0.0166）；受影响配对读数很明确（相对于 −0.031 零假设为 +0.1754 [+0.0705, +0.2895]）；无标签留出 rho 在全部三个评估工具类别中都把 oracle 排在每个错接替代之前。一次边界放松不能修复交换。

**chrX 答案：否。**chrX 只有 pooled 读数能检测到 ≥80 Mb 墙，无规范 splice 能检测到 ≥60 Mb 墙。

**更正后的原因。**早先的解读只归因于训练深度。深度扫描（`test_res/010/011/012`）否定了这一点：无规范 splice 在 chr1 从 16,928 降到 5,209 条定相记录的**每个**深度都能检测到 5 Mb 墙，但在同样 5,209 条记录下，chrX 检测不到 60 Mb 以下的墙。实际驱动因素都已测量（F17）：

- **定相率**——chrX 为 15.3%，常染色体为 31.0%，且沿染色体均匀，因此 chrX 的 oracle 只用少 3.3x 的已知拷贝接触拟合；
- **覆盖均匀性**——chrX 的 168 个 bin 中有 10 个没有定相训练接触（chr1：0），所以 FDG 主链有空洞，oracle 自身的留出 rho 为 0.4525，而 chr1 为 0.6389；
- **留出配对数**——1,059 对 1,622。

两条染色体的两份拷贝同样不同（拷贝间距离矩阵 rho 0.171，平均相对分离 0.47）。信号相当，但**尺子**不同。

**因此：**

- chr1 的目标不必限制在粗糙片段尺度；在**完整深度**下，L2 是合理目标。
- 支持的片段尺度是**（定相深度 × 覆盖均匀性 × 留出配对数）**的函数，而不是深度本身，也不是染色体本身。chr1 与 chrX 是该轴的两个端点。任何逐染色体主张旁边都要写出三个数字。
- 预注册决策规则适用于单次比较，但作为检测限曲线的**估计器并不可靠**：阈值是一次有噪声的抽样（在扫描中为 0.0092–0.0357）。绘制曲线时报告带 CI 的效应量，不要只给标志。
- 无标签判据可以作为 Stage 2 的选择目标，规范不变和受影响配对读数是敏感形式。
- 退出码为零本身不是成功：拟合噪声底（半数据 oracle 重拟合可使分数移动最多 +0.052）大于 20 Mb 效应，因此 pooled chr1 结果必须始终带 CI。

### Stage 2——全基因组等位基因拆分（当前）

完整计划：**`docs/PLAN-genome-allele-split.md`**。摘要：

- **范围。**在一个共享核体积中联合拟合 40 条轨迹（20 条染色体 × 2 个拷贝），使用全部 1.7M 条接触，包括 inter。没有训练/测试拆分。
- **当前 V1 训练状态。**正式运行 `test_res/020-20260913_071841-v1-p9016-joint` 已完成 5 Mb -> 2 Mb -> 1 Mb 的全数据训练，使用 5,290 个物理珠子和 40 条轨迹。`random_joint` 由最终 1 Mb `count_nll_normalized` 选中（`9.593585931292237`，`consensus_joint` 为 `9.598781292397067`）。六次阶段尝试均达到固定迭代预算并以 `not_converged` 结束；见该运行的 `selection.json` 和独立 `termination_audit.json`。这是已完成的训练记录，不是 L2 证据；完成报告为 `test_res/020-20260913_071841-v1-p9016-joint/evaluation-20260913_080300-final/README.md`。其 R1/R2/R3 读数仍只用于评估，不改变 L2 状态。
- **实测可行性。**全基因组 1 Mb / 40 条轨迹每次 FDG 迭代 0.375 s，1000 次迭代 375 s，在相干数据上收敛（RMS_force 0.0010）。2 Mb：118 s。5 Mb：22 s。`-I` 支持重采样的多分辨率热启动。
- **引擎提供共享 excluded volume，而不是有限核球。**FDG 排斥没有染色体判据，因此 40 条轨迹共享一个 excluded volume；主链力仍限制在染色体内。它没有显式径向 confinement 势。inter 接触作为接触力进入。
- **核心仍是 `u = 0`。**全基因组拟合和 inter 接触**不会**打破 `2^20` 拷贝标签对称性（见严格边界条目）。残差反演加非线性 phase retrieval 是历史提出的路线，不是当前 V1 实现。获授权的 V1 路线是 `docs/RECONSTRUCTION_V1_PROTOCOL.md` 中的有限接触核联合坐标拟合；019 恢复校准通过了数学和实现 gate，但只把中断运行中共同的 1 Mb `iter50` 检查点定格下来。登记的 80 次校准迭代未完成，不能建立 L2。
- **读数。**R1 逐接触准确率（含两个上限）、R2 结构一致性，以及作为 L2 主要数字的**R3 片段一致性**（`frac_consistent`、`longest_run`、`n_walls`）。

## 报告规则

1. 逐接触准确率绝不能脱离 oracle 上限单独打印。
2. 绝不报告由部分定相 oracle 产生的 oracle。Oracle 只能使用完整定相接触，在训练折上拟合、在测试折上评分。
3. 绝不报告两结构增益而不同时给随机拆分和共识对照，以及逐染色体胜出数和 bootstrap CI。
4. 绝不按“两个结构有多不同”给扰动打分。`1 - rho(dA, dB)` 会被大的随机场最大化（随机场相对于真值 0.27 可得到 0.71–0.85）。使用相对于真结构的 matched-minus-swapped，并提供 `u = 0` 和 random-`u` 对照。
5. 每个 E-step 都带符号断言（真结构的 hard assignment 必须超过 0.55；已测 0.6597）。
6. 结构尺度未校准——按秩或经过 Procrustes 后比较。
7. 高的拷贝内相关不等于同源拷贝恢复；始终报告综合读数。
8. 写明结果实际支持 L1、L2 或 L3 中的哪一项。
