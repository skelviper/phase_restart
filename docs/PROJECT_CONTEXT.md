## 研究对象与当前结论

项目目标是从去掉单倍型列的 `data/P9016.pairs.gz` 重建 P9016 小鼠单细胞二倍体三维结构。拟合对象为 20 条染色体的 40 条拷贝轨迹，全部放在一个共享核体积中，使用全部 `1,703,888` 条接触：`1,135,454` 条染色体内（`intra`）接触和 `568,434` 条染色体间（`inter`）接触。参考 `data/P9016.1m.3dg.gz` 是 1 Mb、40 条染色体拷贝轨迹，仅供评估器在候选坐标写出并完成哈希后读取。

项目不是逐染色体独立重建。染色体间接触没有母源/父源标签信号：同单倍型 `70,558`，异单倍型 `76,438`；但它们提供染色体空间分区和核内装箱的空间约束。标签准确率和空间放置是两个独立读出，不能因前者无信号而删掉后者。全数据中的 `1,135,454` 是染色体内接触，不应把它与拷贝标签类别 `cis`/`trans` 混称；后者另有 `342,911` 个 `cis` 和 `6,114` 个 `trans`。

三项结论的适用状态如下：

- **L1（有预测信号）**：chr1 相对同记录集随机拆分的差值为 `+0.0767 [+0.0480, +0.1045]`（F16）；chrX 为 `+0.0400 [+0.0007, +0.0914]`，发生在 `891/1,059` 对上，属于边缘证据。chrX 的分相率为 `15.3%`，常染色体为 `31.0%`；chrX 的 oracle 由少约 3.3 倍的拷贝已知接触拟合，留出 bin 对集合也小 35%。
- **L2（整条染色体一致）**：尚未证明。第 1 阶段证明评分能区别染色体范围内的一致拆分与预注册的全局错接（主要在 chr1），但未证明盲方法能找到它。不得把 oracle 或评估工具上限写成盲恢复。
- **L3（无 SNP 方法不可能）**：已撤回。当前证据只否定随机初始化、软 E 步骤、线性相位恢复、共识几何符号图在当前硬分配 + 原生 FDG 循环、当前数据深度下的表现，不否定非线性求解器这一类。

L1 不推出 L2。每条染色体的 A/B 全局标签是规范自由度；真正的问题是 `u_c` 沿整条染色体是否形成连续一致的场，而不是任意片段是否局部相似。

## 计数对称性与隔离

令 `u_c = (X_c - Y_c)/2`。计数目标对任意染色体的 `u_c -> -u_c` 不变，存在精确的 `2^20` 对称性。加入染色体间接触也不能消除每条染色体的 A/B 标签规范自由度；方法必须显式离开 `u = 0`。计数对整个向量 `w` 是偶函数，不只是共识方向上的 `delta^2`；横向扰动会同时改变两条距离。

训练侧不得读取 `phase0`、`phase1`、`phase_prob00..11`、其派生物或参考 3DG。`run.py prepare` 的训练文件恰好七列，真实输出为 `inputs/P9016.snpfree.pairs.gz`，清单写入 `inputs/manifest.json`；遇到带 phase 字段的 `#columns` 必须拒绝。评估器只有在候选坐标写出并完成哈希后才能读取 phase/reference。当前 Reconstruction V1 用全接触、无标签计数似然选择候选，不能使用参考结构选择超参数、停止或候选。

旧第 0/1 阶段的留出协议与 V1 的全数据计数目标必须分开叙述。20 条染色体来自一个细胞；bootstrap 只描述该细胞内的技术/结构变异，不构成生物学重复。

## 更正后的基线与旧判据

旧无标签判据的形式是：候选结构在训练折上由原生 FDG 拟合，再在留出 bin 对计数上以 Spearman 比较 `d_A^-a + d_B^-a` 与观测总数，距离指数 `a` 只能在验证折选择。它属于旧第 0/1 阶段评估检验，不是当前 V1 的训练协议。

第一代结果有四类协议缺陷，后续冻结基线已修正：

1. 坐标必须数值比较。`c[2] > c[4]` 的字符串比较丢掉 `147,005/1,135,454` 条染色体内接触（`12.95%`）；chr1 单独丢掉 `14.10%`。
2. 数据折不得由基因组距离函数产生。`(i*7919 + j*104729) % 2 == (i+j) % 2`，因此同区间对全落入 `test`；修正版使用数值 bin 对的混合哈希和训练/验证/测试折。
3. 距离指数只能在验证折选择，不能偷看测试折。
4. 同区间/零距离对从结构指标排除，单独计数 `438,774/1,135,454`（`38.64%`），它们不含结构信息，也是旧“并列”的全部来源。
5. 每个双拷贝比较都需规范不变。原生双拷贝拟合的标签不对称曾使 chr1 留出 rho 变化 `0.0220`；使用候选结构及标签互换版本、oracle 及互补版本的均值，或使用 `rewire` / `splice`。
6. `hickit -s` 不是独立重复。旧 F14 的逐字节相同结果受 `-s` 位于 `-b` 之后影响；正确随机种子仅是初始化重复，独立拟合需更换数据。
7. `hickit -b` 边解析边 FDG 拟合，`-n` 必须先于 `-b`（如 `-n 3000 -b1m`）。
8. V1 当前没有训练/测试拆分；所有接触拟合每个候选，超参数只看无标签计数似然。

修正版全 20 条染色体基线（排除同区间对）：双结构 oracle `0.5856`、随机拆分 `0.5127`、单结构共识 `0.5087`；`oracle-random` 为 `+0.0729 ± 0.0520`，19/20 染色体 oracle 胜，15/20 的逐染色体 bootstrap 置信区间不含 0。chrX 差值 `-0.090`，chr7/14/17/19 的区间跨 0。早期错误协议曾报 `0.689 / 0.648 / 0.641` 和 `+0.041`；修正后的差值更大，不是更小。绝对 rho 受共享成分主导：chr1/2/3 的基因组距离为 `0.47/0.44/0.52`，共识三维结构为 `0.63/0.59/0.63`，oracle 为 `0.64/0.58/0.59`；应看配对差值，不看绝对值。

## 已验证事实与障碍说明

| 编号 | 事实 | 数值或说明 |
| --- | --- | --- |
| F1 | 染色体内接触的拷贝关系 | `342,911` 个 `cis` 对 `6,114` 个 `trans`，`98.2%` |
| F2 | 染色体间接触无标签偏向 | `same` `70,558`，`different` `76,438`，约 `1:1` |
| F3 | 参考结构可区分已完整分相、同染色体同拷贝（cis）接触的拷贝归属 | 排除同区间后 `76.2–81.2%`，chr1 `0.7903` |
| F5 | 参考两套拷贝确实不同 | `mat/pat` 距离相关系数 `0.34` |
| F6 | 随机初始化的硬 EM 停滞 | 8 轮评分/真值 rho 约 `0.02–0.03` |
| F7 | oracle 初始化的硬 EM 保持 | 6 轮 rho 约 `0.33–0.37` |
| F9 | oracle 胜随机初始化 | `+0.073`，19/20 条染色体 |

去掉同区间后，参考准确率为：chr1 `0.7903`、chr2 `0.8111`、chr3 `0.8063`、chr4 `0.7797`、chr5 `0.7726`、chr6 `0.8122`、chr7 `0.8026`、chrX `0.7616`，无残留并列；旧 `0.866` 是伪影。

计数只确定 `lambda_A + lambda_B`，对半差场 `w = (X - Y)/2` 为偶函数。正确结论是：拆分符号不是计数的一阶信号，`w = 0` 有零一阶导数并是硬分配循环的自洽固定点；但偶性不表示所有方法中 `w = 0` 都是稳定吸引子，`(u^2-1)^2` 在 0 处为驻点且 0 是局部最大值。此前“只依赖共识方向的 `delta^2`”也过强：横向扰动保持 `d_A-d_B` 不变，却会把两条距离都移到 `sqrt(1+t^2)`，因此改变总和；可观测量对整个 `w` 为偶函数。`/work/phase4` 已在无 SNP、无参考输入的情况下完成观测模型和共用结构实验，不应重新包装成新想法。

“硬分配 + 原生 FDG”不是概率 EM：FDG 的接触目标距离按 `d_scale = pow(n_eff, -1/3)` 缩放，而 E 步骤用另一个距离比规则；本应分成 6/4 的 10 条接触可能变成 10/0，不能套用 EM 收敛定理。

## 第 0 阶段、第 1 阶段与历史计划

第 0 阶段冻结脚本是 `docs/exploration/benchmark_v1.py` 与 `explore_estep_fixed.py`，冻结前不得改写基线。第 1 阶段正式运行目录是 `test_res/007-20260912_124000-stage1-fragment-swap-chr1`、`008-20260912_124000-stage1-fragment-swap-chrX`、`009-20260912_124000-stage1-depth-control-chr1-as-chrX`，设计在 `docs/STAGE1_PREREGISTRATION.md`，数字在 `docs/MEASURED_FACTS.md` F13–F20。

第 1 阶段的历史问题是：评分能否把染色体范围内一致拆分与局部正确但全局错接的拆分区分开。原计划的最小设计为 chr1、1 Mb、固定 20 Mb 片段、独立 oracle 正对照；在同一测试折上比较完全一致的 oracle、预注册片段交换、随机拆分和共识，并给边界松弛、片段内、短程跨片段、长程跨片段与总体留出 rho。若交换拆分与 oracle 不可区分，目标才应限制到数据支持的片段尺度；这只是 oracle 评估检验，不是盲恢复。备用方案曾考虑 raw BAM/FASTQ 的同分子多路接触，但当前 `1,703,888` 个 `readID` 全为 `.`，`.seg` 也不会自动使问题可识别。

当前结果：chr1 的汇总规范不变判据检测到 20 Mb 分界墙，差值 `+0.0243 [+0.0055, +0.0434]`；无规范的 `splice` 工具检测到 5 Mb 和 10 Mb 分界墙，差值分别为 `+0.0151`、`+0.0166`；受影响对读出为 `+0.1754 [+0.0705, +0.2895]`，相对零假设 `-0.031`；三类工具都将 oracle 排在全局错接方案之上，一轮边界松弛不能修复交换。chrX 的汇总读出只能检测至少 80 Mb、`splice` 至少 60 Mb 的分界墙。

深度扫描（`test_res/010/011/012`）显示原因不是深度单因素：chr1 在 `16,928` 到 `5,209` 条已分相记录各深度都能由 `splice` 检测 5 Mb 分界墙，而同为 `5,209` 的 chrX 在 60 Mb 以下检测不到。关键量为分相率（chrX `15.3%` 对常染色体 `31.0%`）、覆盖均匀性（chrX 的 168 个区间中 10 个没有已分相训练接触，chr1 为 0）和留出对数量（`1,059` 对 `1,622`）。在覆盖空洞对应的原始 oracle 留出评分中，chrX 为 `0.4525`，chr1 为 `0.6389`。chr1/chrX 的拷贝间距离矩阵 rho 都是 `0.171`，平均相对分离度为 `0.470` 对 `0.476`，说明信号类似而标尺不同。预注册决策阈值是一次带噪抽样，在深度扫描中为 `0.0092–0.0357`；它适合单次比较，不适合估计检测极限曲线，曲线应报告效应量与置信区间。

第 1 阶段的拟合噪声底也须保留：两个不相交半数据 oracle 重拟合相对全数据 oracle 的差值为 `+0.0520 [+0.0271, +0.0782]` 和 `+0.0100 [-0.0085, +0.0296]`，最大值超过 20 Mb 分界墙效应，因此汇总 chr1 结果必须带置信区间。F20 独立审计对正式运行的 `167/167` 项一致、0 个不一致项；chr1 独立 20 Mb `splice` rho 为 `0.6074848012069358`，73 个坐标的哈希门无缺失或不匹配。

历史第 2 阶段计划曾提出“局部双结构候选 -> 同步拷贝对应关系 -> 全局几何细化”：冻结 FDG 共识的 `Z` 并搜索 `Z ± u` 会因共识不是中点（Rg `3.05` 对 `1.80`）而排除真配对，须让 `X`/`Y` 一起更新；重叠窗口 `{A1,B1}`、`{A2,B2}` 的对应关系要由重叠几何、跨窗口接触和链连续性决定。该路线原本要求先在合成双聚合物数据上验证零噪声、已知抽样噪声、真实稀疏度，以及两结构相同的阴性对照；单一未经验证的确定性初始化失败只能算方法局限，不能当作数据不可恢复的证据。当前 V1 路线已改为下节所述的有限接触核联合坐标拟合。

## 第 2 阶段 / Reconstruction V1

完整设计见 `docs/PLAN-genome-allele-split.md`、`docs/RECONSTRUCTION_V1_PROTOCOL.md`。目标是一个联合拟合：40 条轨迹、20 条染色体、共享核体积、全部 1.7M 条接触（含 `inter`），不采用训练/测试拆分。原生 FDG 提供共享排斥体积，不提供有限核球；排斥力没有染色体判定，主链力留在染色体内，径向约束不是显式势，染色体间记录以接触力进入。

020 正式运行完成 `5 Mb -> 2 Mb -> 1 Mb` 全数据训练，5,290 个物理珠、40 条轨迹。最终 1 Mb `count_nll_normalized`：`consensus_joint=9.598781292397067`，`random_joint=9.593585931292237`，故选择 `random_joint`。六个阶段到固定迭代预算后均为 `not_converged`；这是完成的训练记录，不是数值收敛或 L2 证据。独立 `selection.json` 与 `termination_audit.json` 记录了选择和终止状态，020 评估的 R1/R2/R3 只能作评估侧解释。

019 恢复校准通过数学和实现门槛，但在中断后只完成并固定了共同 1 Mb `iter50` 检查点；注册的 80 步校准未完成，不能建立 L2。残差反演加非线性相位恢复仍是历史提出的路线，不是当前 V1 实现；当前授权路线是 `docs/RECONSTRUCTION_V1_PROTOCOL.md` 的有限接触核联合坐标拟合。

022 延续拟合接受 `240 -> 480` 的 240 步，终态 `budget_not_converged`；原生 FDG 提案因无标签 `total-J` 没有改善而为 `rejected_no_label_free_improvement`，保留延续终点。20/20 条染色体、同一共同掩码的 R2：延续相对 V1 原始结果的 `similarity` 差值为 `-0.000890817628`（CI `[-0.004060498973, 0.002427151962]`），`contrast` 差值为 `-0.000221703680`（CI `[-0.004748627202, 0.004092863791]`），均 `9/20` 胜出；R2 没有选择终点，也不改变 L2。

可行性记录：1 Mb/40 条轨迹每次 FDG 迭代 `0.375 s`，1,000 次迭代 `375 s`，连贯数据可收敛到 `RMS_force 0.0010`；2 Mb `118 s`，5 Mb `22 s`；`-I` 支持重采样的多分辨率热启动。主要 L2 读出是 R3 `frac_consistent`、`longest_run`、`n_walls`，并与 R1（含两个上限）和 R2 一起报告。

## S0 重评估与 020 交付读出

`split` 是旧版全基因组 S0 命令，不是 Reconstruction V1。它接受 `--genome`，只读去单倍型列的训练输入，最终评估网格固定为 1 Mb；V1 使用独立的 `run.py reconstruct` 和冻结的全数据计数目标。对既有共识、随机和 oracle 坐标做新评估可运行：

```bash
python run.py reevaluate --source test_res/014-20260912_153000-s0-genome-wide-fixed
```

该评估不重新拟合。正式当前结果是 `test_res/017-20260912_200040-s0-reevaluated`；`016` 仅因 fig6 坐标轴标签被裁切而标为已替代，`015-20260912_194540-s0-reevaluated` 只有取消通知，不应报告。评估器使用几何拷贝规范、两个上限和明确分母；单轨共识不是双拷贝对比。

020 最终评估报告是 `test_res/020-20260913_071841-v1-p9016-joint/evaluation-20260913_080300-final/README.md`，在同一细胞、20 条染色体的共同 `200,898` 条记录上汇总：R1 为 `selected` `53.95%`、`fixed-random` `50.72%`、`oracle-fit` `63.21%`、`reference` `78.72%`；配对 R1 为 `+0.032277`，CI `[+0.009545, +0.054825]`，胜出数 `14/20`；R2 为 `delta=+0.111530`，CI `[+0.068857, +0.157703]`，胜出数 `18/20`；R3 为 `delta=+0.074663`，CI `[-0.010580, +0.161255]`，`132/138` 个片段，平均 `1.90` 道分界墙。区间描述同一细胞内的技术/结构变异，不是生物学重复；六个 020 训练阶段都以固定预算 `not_converged`，这些读出不改变 L2 未证明的状态。020 是 Reconstruction V1，与旧版 S0 及旧留出协议分开；评估器当前只做报告整理，不应预期新拟合或指标改变。

## 报告与文件边界

不得在没有 oracle 上限的情况下报告逐接触准确率；不得报告由标签不完整数据产生的 oracle；两结构增益必须配随机拆分、共识、逐染色体胜出数和 bootstrap 置信区间。不得用 `1-rho(dA,dB)` 评价恢复：这是实证上错误的读出，随机场会给出 `0.71–0.85`，而真值只有 `0.27`。每个 E 步骤需符号断言（真结构应 `>0.55`，实测 `0.6597`），结构按排序或 Procrustes 比较；拷贝内相关高不等于同源拷贝恢复，必须报告综合读出。

`native/hickit/` 的随仓库提供的原生源码、`source_snapshot`、`frozen_protocol`、`archived020` 和第三方文档属于不可改字节对象；`native/hickit/PROVENANCE.md` 是项目自有说明文档，按活动文档规则处理，但不得改写其中的 hash、路径和溯源事实。被 `pr/reconstruct.py:421-423`、`continuation.py:650-658` 按哈希锁定的 `docs/RECONSTRUCTION_V1_PROTOCOL.md` 同样保留原路径与哈希；中文译本为 `docs/zh_archive/RECONSTRUCTION_V1_PROTOCOL.zh-CN.md`，总索引为 `docs/zh_archive/README.md`。相同内容只翻译一次，索引列出全部原件路径。
